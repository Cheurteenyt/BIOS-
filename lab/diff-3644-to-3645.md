# 3644 → 3645 diff — what the update actually changes

Date: 2026-09-17. Inputs: `vendor-acq-3644-download.CAP` (sha256
c3db78fe…) vs `3645-analysis/TUF-GAMING-B550-PLUS-WIFI-II-ASUS-3645.CAP`
(sha256 4c124210…), both 33,558,528 B, same CAP GUID header
(8ba63c4a-7723-48fb-803d-578cc1fec44d).

## Measured deltas

- **43 changed regions** over 32 MiB; the payload is concentrated in:
  - the **main boot FV @ 0x451000 (11.3 MB)**: one replaced module block of
    **3,372,544 B** (0x58be00-0x8c3400) plus a 13.3 KiB region
    (0x459e00-0x45d200);
  - the **NVRAM/setup FV @ 0xf21000**: 63 KB + 11 KiB changed;
  - ~20 scattered 512 B stamps (version/checksum fields, one per module).
- String deltas inside the replaced block are mostly compressed-noise, but
  the clear semantic markers are **X.509 certificate timestamps**:
  `260805000000Z`, `260910084920Z`, `260910084931Z`, `260910084944Z`
  (NotBefore/NotAfter in 2026) — a **signing-certificate rollover** — plus
  a build date `09/10/2026` where 3644 carried `08/18/20`-era markers.
- AGESA markers present are identical in both ("AGESA Driver"); no new
  AGESA version string is visible in plaintext (the modules are
  compressed, so a sub-version bump cannot be excluded, but nothing
  suggests a major AGESA landing).

## Verdict

"Improve system compatibility" = a replaced boot-module block (contents
opaque without full FFS decompression), a signing-cert rollover for future
updates, and NVRAM default touches. **No evidence of a reliability or
performance feature that the founder needs.** Recommendation stands: no
update; keep 3644. The diff artefacts stay in
`3645-analysis/` for a future re-check (the certificate rollover means a
future security-relevant update will land on top of this build).
